# V2 clarify-plan, check-in and implementation

**Date:** 2026-10-26  
**Base:** `7ca69084` plus the C1 PR diff  
**Mode:** deterministic mocked agents and Taskbot adapter; real Factory runtime,
durable storage, authenticated HTTP server and Chromium dashboard. Publication
unit scenarios mock Git and the forge. No live model, webhook or forge requests.

These changes affect human waits, answer publication and recipe orchestration,
so F1 is applicable. The browser scenario exercises the bundled recipes rather
than a parallel test-only graph. All state uses a temporary Factory home removed
on exit; production configuration and tickets are untouched.

## Browser drive

After `pnpm install && pnpm build`, run:

```sh
F1_AGENT_MODE=mock F1_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
  bun scripts/qa-v2-check-in.mjs
```

Port defaults to 3674; override with `F1_CHECK_IN_PORT`. The fixture uses the
repository's authenticated Factory server and the same Playwright setup as
`scripts/qa-display-node.mjs`. It asserts:

- `v2-clarify-plan` receives the original launch prompt through declared reads,
  asks through Display, and publishes the exact `/view-answer` protocol to mocked
  Taskbot. A ticket-command reply resumes clarification and emits both ports.
- A standalone `v2-check-in` preserves its exact waiting document, digests and
  bound plan/proposal across a cold restart; neither author nor reviewer reruns.
- At 390px, a per-point comment and Request changes reach the resumed author.
  The revised proposal renders; Accept finishes without mandatory item answers.
- Desktop and 390px have no page overflow. No browser page errors occur.

The deterministic title and proposal are fixture outputs, not evidence of model
quality. Ticket answers use the runtime's explicit ticket-command parser; live
webhook transport is outside this drive.

## Focused acceptance and regressions

From the repository root:

```sh
pnpm --filter ./packages/edge-worker exec vitest run \
  test/V2PlanningRecipes.test.ts test/DisplayNode.test.ts \
  test/TicketTracking.test.ts test/HumanViewsRuntime.test.ts --maxWorkers=2

pnpm --filter ./packages/edge-worker exec vitest run \
  test/AgentNode.test.ts test/NodeGuarantees.test.ts \
  test/FactoryRecipeGraph.test.ts test/RepositoryIONodes.test.ts --maxWorkers=2

pnpm --filter ./packages/edge-worker typecheck
```

The C1 tests execute the actual bundled sub-recipes standalone, validating mock
agent results against their output schemas. They cover API and ticket question
round-trips, a rejected plan review and resumed plan, routine work skipping the
display, automated proposal rejection, human request changes and optional
per-point comments, rejected stale acceptance after a plan change, `revise-plan`,
bound Call composition, restart while waiting, implementation assistance and
`to-architecture` without publication. The successful implementation scenario
executes the real Git/PR node executors against mocked transports, verifies
`--no-verify`, push and one draft PR creation, and asserts complete `change`/`pr`
ports including the resulting repository head.

The source-context regression preserves unmarked legacy `@source`. The display
publication regression asserts new-engine protocols reach the tracking hook while
legacy lifecycle milestones stay disabled. Existing agent, node-guarantee and IO
tests cover native session policy, scoped freshness, bound recovery and effect
reconciliation; these do not constitute live provider validation.

## Scope retained for D1

No legacy implementation was deleted: Factory/Takeover still call `clarify-plan`,
`architecture-review` and `implement-work`. Their `askQuestions`, record-decisions,
architecture decision/gate/proposal state, checks and fixed pages, draft-pr tool,
stock prompts and instruction snippets remain referenced. D1 must switch the
composition before removing those paths. The two generic additions are the
documented new-engine launch `@source` and validated Display protocol publication;
there is no recipe-specific node, engine dispatch or dashboard component.
