## Workflow assertions

- No-UI work skips capture and emits `qa.needed=false` with empty evidence.
- Failed visual review runs a resumed fixer, commits/pushes, recaptures the changed
  scenario and passes; the unrelated scenario executes once and is reused.
  Corrected work returns `to-review` for the composition's code/CI gates.
- A guide generated as a Display document accepts explicit approval with item
  comments through the real answer API.
- A new head while the human is reading makes that approval stale; it cannot
  create an authorization and routes through the fixer/publication path.
- Request changes runs the human fixer and publishes before returning `to-review`.
- A minor correction carries approval after current provider checks; a second
  minor correction still compares against the original human-approved heads.
- A meaningful correction presents a new guide. A later human rejection disables
  carry-forward until renewed explicit approval, even if a subsequent impact
  assessment would otherwise claim safety.
- A two-port consumer binds the actual `explicit` or `carried` producer and checks
  `fresh(approval)` without knowing any sibling paths. Required CI failure routes
  to `to-ci` before the guide.
- Generic media refs work without legacy capture adapters. Display and media APIs
  verify source freshness and exact bytes, survive a runtime restart, stream video
  ranges, and reject replacement or a changed dependent source.
- Nested code tours validate head/base line references. File checks reject
  absolute paths outside the evidence root and escaping symlinks.

- Both a failed capture and a passed capture disputed by review execute again at
  an unchanged source HEAD; the independent unaffected scenario still executes once.
- Repeated capture failures and repeated review complaints pause at `qa-help`
  after three observations, before visit exhaustion. An authenticated Retry QA
  answer executes capture again and never creates a passing QA receipt itself.
- Review findings name verified scenario IDs. The approval handoff refuses an
  unstamped review or QA port, and repeated approval visits refresh their actual
  executed review/QA producers before attempting carry-forward.
- Explicit approval records the provider-confirmed ready state; carry-forward
  faithfully retains a provider draft state instead of claiming it is ready.
- Media unit checks retain more than 2,048 historical entries while accepting a
  replacement capture. Active evidence from other steps plus the whole new batch
  still obey both limits. Rejected batches retain no partial assets; duplicate
  candidates and idempotent retries preserve stable indices without double charging.
- The fix commit's pre-commit checks passed Biome, full workspace build and workspace
  typecheck. The conflict resolution preserves the C1/C2/C3 recipe registrations
  and their contract documentation, including the C5 takeover intake addition.
