## Remaining handler classification (complete switch and pre-dispatch)

- `inspect-existing`: action: fetches/inspects existing PR and Git, stores takeover source/PR context, enforces branch/base isolation; retain.
- `impact-checks` pre-dispatch: action: runs selected configured scripts and retains immutable revision-bound receipts; retain.
- `record-decisions`: action: publishes retained clarified decisions through publication policy; retain.
- `draft-pr`: action: validates completed implementation, creates/pushes commit/branch and draft PR/MR (or continues takeover), retains grouped delivery results; retain.
- `ci`: action/passive watcher: fresh provider/Git reads, retry state/receipts, feedback assessment, CI infrastructure supervision, revision/base/impact protections and waits; returns outputs for routes; retain.
- `ci-fix-readiness`: action: fresh provider/Git/scope/feedback evidence, refreshes bound CI output, reports/saves and returns skipFix under unchanged accepted review/QA/guide safeguards; retain explicit queued-fixer preflight.
- `handoff`: action: validates current review/QA/media/guide/CI/external evidence, publishes guide/PR state and saves readiness; confirmed already-merged recovery is retained. Stock outputs drive branches; old handoff route adapter stays frozen-only.
- `merge`: action: verifies exact human approval/current evidence, invokes provider merge and retains uncertain/pending/confirmed recovery receipts; mixed delivery pending remains blocking; retain.
- `external-apply`, `external-verify`, `external-final`: actions: integration applies idempotent authorized intent, independently fetches/verifies or performs fresh final state check (updates delivery verification/final receipts); retain.
- `external-guide`: action: requires independent completed verification, builds guide, refreshes bound guide and saves; retain.
- `human-review`, `architecture-decision`: human checkpoints; approval/proposal identities and passive waits owned by runtime; retain, no premature views work.
- `exec`: action: external MCP or process invocation with argument binding; retain.
- `script`: action: process execution with input-file/evidence/repository env and bounded output; retain.

No additional purely decision-only FactoryTools handler exists at this base. GroupedTools projects the above actions per repository and joins confirmed results; it is not an additional decision-only catalog entry.

## Implementation decisions

1. Check evaluation remains pure, uses #136's generator/budget/rule language, named reads, explicit fixed evidence checks and ordinary branches. Add all/any/count/filter result aggregation over arbitrary collection paths; do not implement For each.
2. Runtime-owned evidence acquisition, convergence and checkpoint waits remain outside the evaluator. Evidence projections authenticate exact declared producer/frame/receipt; input names alone cannot activate a role. Every new recovery target is declared in recipe routes; deterministic old adapters preserve frozen/saved/forked definitions without rewriting accepted state or native conversations.
3. Keep contract freezing as an explicit action. Keep required fresh provider evidence acquisition and side effects as actions; Check calculates routing results from their outputs and declared fixed evidence.
4. Preserve historical 675 stock/frozen role prompt variants; only capability reference and its entire expected prompt change for Check.
5. Validate final integrated source with required local gates/audit, repository plus external/mixed mocked F1, actual editable Check desktop/390 light/dark screenshots and proportional compiled-binary smoke. No active-run edits/deployment, no #138–#148 work.

The named result/projection shape is the intended mechanism change: Check adds
`passed`, explicit result names and generic collection results. Missing selected
optional data is `null`; routing still uses the same true/false decisions.
Post-fix invalidation is visible as configured `baseChanged`, `reviewRequired`
and unchanged-revision/failure/work results alongside the action's full factual
head/base/feedback observation, instead of a decision-tool-owned next-step policy.

Rule budget/resource errors remain hard failures. No failure is converted into
an approval. Fixed evidence and original receipts remain the authority at action
boundaries, so changing a Check result cannot manufacture source evidence or human
approval. The temporary eager-input/subset experiment was removed: named rules
retain bounded selected traversal and ordinary `reads` throughout.
